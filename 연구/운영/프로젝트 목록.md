# 연구 프로젝트 목록

연구는 고객·사업과 검사 대상에 부여한 고정 프로젝트 ID로 구분한다. `ai_solution`은 여러 저장소에서 사용하는 코드 폴더명이므로 프로젝트 식별자로 사용하지 않는다.

| 프로젝트 ID | 표시 이름 | 프로젝트 노트 | 코드 위치 및 상태 |
|---|---|---|---|
| JY-METALRING | 진양 철환 앞뒤 판정 | [개요](../프로젝트/JY-METALRING/개요.md) | `E:/DH/Gitlab/Jinyang2026/ai_jyos_2026/ai_solution` |
| JY-GRIPPER | 진양 진공 그리퍼 이상탐지 | [개요](../프로젝트/JY-GRIPPER/개요.md) | 같은 저장소. 연구 상세 기록은 미정리 |
| RESEARCH-DINOPATCH | 공통연구 Dinopatch | [개요](../프로젝트/RESEARCH-DINOPATCH/개요.md) | 기존 Dinopatch 연구에 연결. 코드 경로는 추후 확인 |

## 구분 기준

- 고객·사업과 검사 대상이 같으면 모델을 바꿔도 같은 프로젝트로 기록한다. 철환의 DinoMatch·EfficientNet 비교는 JY-METALRING에 속한다.
- 같은 저장소라도 검사 대상과 평가 기준이 다르면 프로젝트를 분리한다. 철환과 그리퍼의 결과는 합산하지 않는다.
- 다른 프로젝트의 방법을 참고하면 원문 링크와 적용한 차이만 적는다. 원 연구의 수치를 현재 프로젝트 성능으로 가져오지 않는다.
- 프로젝트 ID는 고정한다. 표시 이름, 모델, 코드 경로 변경은 개요에 기록한다.

## 저장 위치

`프로젝트/<프로젝트 ID>/` 아래에 `개요.md`, `실험/`, `일지/`, `첨부/`를 둔다. 실험 노트는 `날짜_프로젝트ID_주제_실행ID.md`, 일지는 `날짜.md`, 첨부는 `첨부/<실행ID>/`로 구분한다.

## 기존 기록과의 연결

2026-10-02에 프로젝트 ID 체계를 추가했다. 다른 세션에서 수정 중인 기존 노트는 이동하거나 덮어쓰지 않았다. 기존 날짜별 일지와 근거 문서는 원래 경로로 연결하며, 이후 기록은 프로젝트별 폴더를 사용한다. 기존 기록의 물리적 이동은 해당 편집이 끝난 뒤 링크를 함께 점검하며 수행한다.
