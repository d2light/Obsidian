# 기록 규칙

- 연구 시작 시 프로젝트 노트와 최근 일지를 읽는다.
- 실험 완료·실패·방향 변경마다 날짜_프로젝트_주제_실행ID로 고유 노트를 만든다.
- 수치는 산출물에서 확인하고 평가조건, 임계값, 원본/합성, 개발/독립 평가를 구분한다.
- 일지에는 요약과 링크, 프로젝트에는 현재 결론과 미해결 과제를 반영한다.
- 다른 작업자의 노트를 덮어쓰지 않고 공통 노트 변경은 직렬로 처리한다.
- Git에는 연구/와 보관함루트.gitignore만 명시적으로 추가한다. 기존 원격 이력은 보존한다.
- 인증정보·플러그인DB·전체 대화·모델·데이터셋은 기록 저장소에 넣지 않는다.
- 실행 결과의 원본 위치와 파일해시를 남기고 핵심 그림만 복사한다.
- 실험 중에는 노트를 저장하고, 매일18:00 한국시간에 하루 변경분을 커밋·push한다.
  최초 연결 확인용 초기커밋만 즉시 수행한다. push 실패는 로컬 기록과 별도로 보고한다.
- GitHub 원격은 https://github.com/d2light/Obsidian.git 이다. 강제push하지 않는다.
- 프로젝트는 코드 폴더명이 아닌 고정 ID로 구분한다. 등록 ID와 위치는 [프로젝트 목록](프로젝트%20목록.md)을 따른다.
- 새 기록은 `프로젝트/<프로젝트 ID>/` 아래 `개요.md`, `실험/`, `일지/`, `첨부/`로 관리한다.
- 프로젝트 ID는 고객·사업과 검사 대상으로 정하고, 모델 변경만으로 새 프로젝트를 만들지 않는다.
- 기존 편집 중인 노트는 이동·덮어쓰기 없이 링크로 연결한다. 기존 모든 세션이 자동 수집되지는 않는다.
