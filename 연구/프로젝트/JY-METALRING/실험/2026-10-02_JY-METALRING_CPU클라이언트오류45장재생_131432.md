# CPU 클라이언트에서 과거 오류 45장 재생 검증

사용자가 기존 모델이 판단하지 못했던 이미지를 실제 클라이언트로 확인하도록 요청했다. 배포용 one-file CPU EXE에 기존 ONNX와 신규 가중 패치 평균 k=1 ONNX를 각각 적용하고 같은 45장을 파일 감시 경로로 입력했다.

## 표본과 조건

기존 현장 모델 P003_01_20260923_154144의 오류 45장을 선택했다. 실제 OK 43장과 NG 2장이다. 전체 사용자 확인 라벨과 파일 SHA256을 대조했고 원본은 그대로 보존했다. 임계값 0, RGB 640×480, CPU ONNX 실행이다. 새 모델은 기존 32개 마스터로 만든 별도 모델이며 현장 모델을 교체하지 않았다.

|---|---:|---:|---:|---:|---:|
| 기존 ONNX | 0 | 43 | 2 | 45 | 43 |
| 가중 패치 평균 k=1 ONNX | 45 | 0 | 0 | 45 | 2 |

기존 모델이 틀린 표본만 골랐으므로 기존 정답 0건은 전체 정확도를 뜻하지 않는다. 이번 결과는 기존 오류 회귀 확인이며 독립 평가가 아니다.

## 실제 확인한 경로

- 수정 없이 실제 `main_client_cpu.exe` 실행, Sanic 시작과 `/api/health` 응답 확인.
- Watchdog 생성·이동 이벤트로 45개 원본을 감지하고 CPU ONNX 예측.
- NG 판정에서만 640×480 JPEG SEG 생성. 생성된 SEG를 재예측하지 않아 정확히 45건 수신.
